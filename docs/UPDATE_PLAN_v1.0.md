## 二、修订要点汇总

### 2.1 数据层保护

Phase 2 的第一步是阅读现有代码，完全沿用现有的 PokedexEntry 结构、稀有度分类标准、stats 格式。
**不发明新规则，不加新字段，不改旧字段。以代码为准，不以方案文档为准。**

### 2.2 地区旅行机制

- 初始地区在新游戏时选择（主菜单新游戏流程中）
- 新地区解锁通过击败当前地区冠军触发旅行事件
- 已解锁地区之间可切换通过背包中的票务道具
- 旅行事件和票务道具复用现有的事件系统和道具系统框架，**不新建底层机制**

### 2.3 进度模型

全局共享一套进度（队伍、连胜、金钱、背包、徽章），切换地区只影响遭遇池（野生宝可梦和训练师）。

> **原因**：每地区独立进度会大幅改动 SaveData 底层结构，违反"尽量不改动底层逻辑"的原则。

### 2.4 图鉴筛选

图鉴界面增加地区筛选功能（下拉或 Tab），可以只看某个地区的宝可梦，也可以看全部。**仅 UI 层改动。**

## 四、依赖关系

**Phase 1 是所有后续 Phase 的前置条件，必须最先完成。**

- Phase 3（题目引擎）和 Phase 2（数据扩展）互不依赖，可以同时进行
- Phase 4（新模式）依赖 Phase 3（需要题目引擎）
- Phase 5（训练师）依赖 Phase 2（需要宝可梦数据）
- Phase 5 完成后，旅行事件链才完整可用（击败冠军 → 解锁下一地区）
- Phase 6（课堂系统）只依赖 Phase 1，可与其他 Phase 并行

## 六、全局约束（每次新会话都要提醒 Claude Code）

1. TypeScript strict mode，不允许 `any` 和 `@ts-ignore`
2. 不破坏现有存档（`SaveData` 新字段 optional + 默认值）
3. 不修改 `peerService.ts` 和 `multiplayer.ts` 的现有代码
4. 宝可梦图片走远程 URL（与现有方式一致）
5. 题目引擎的 `explanation` 字段不能为空
6. Tailwind only，不写 inline style
7. 新数据必须严格沿用现有文件格式，不自定义字段或规则
8. 底层逻辑（战斗公式、经验值生成、稀有度生成、事件框架、道具框架）**不改动**
